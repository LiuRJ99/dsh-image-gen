# CPA-only Option A integration notes

This fork remains an adapter around `@LiuRJ99/dsh-cpa-plugin`'s `IMAGE_GENERATION_SERVICE`. The two protocol families are `gpt` (GPT image models) and `gemini` (Gemini image models); the CPA Host may expose multiple concrete models for each family through its redacted image catalog. The service keeps `generate` backward-compatible while optionally exposing `edit` for reference-image workflows. The adapter does not resolve, persist, or transmit Google/OpenAI/Seedream/DashScope credentials, provider IDs, endpoints, or native `credentialRef` values.

## Adopted provider-neutral capabilities

- **Engine/model controls:** the settings card selects a concrete model from the CPA Host catalog while keeping GPT/Gemini protocol-family controls. GPT receives only `size` (`1024x1024`, `1024x1792`, or `1792x1024`); a legacy `aspect_ratio` is adapter-mapped and never forwarded. Gemini receives only `aspectRatio` and `imageSize`. CPA owns model validation, authentication, and protocol details.
- **Result compatibility:** generated bytes are validated before attachment admission; the output includes a text result and an image content block, with a JSON-safe `attachmentMeta` projection. Legacy `resultView.content` and modern `block.content` image references are both read defensively.
- **Inspiration:** the browser can address only the fixed case/category/style/scene allowlists. The guaranteed release content is the compact built-in catalog and generated SVG previews; the optional Host refresh path uses fixed HTTPS source candidates, bounded streams, an immutable release pin, and an optional `~/.dsh/cache/dsh-image-gen/inspiration` cache. The browser cannot submit an arbitrary URL. Third-party requests are optional and failures do not affect CPA generation; a future release must publish the compact snapshot at the pinned ref before remote refresh is treated as a content source.
- **Gallery:** Better Sidebar Gallery keeps DB version 3, engine/unknown normalization, sharp thumbnail/full-image routing, and virtualization for Grid/Table. Favorites, tags, workspace metadata, and save diagnostics are optional schemaless fields, so no DB v4 migration is required and old records remain readable. It adds favorites, batch selection/deletion, workspace filtering, prompt copy, and CPA-only regeneration. List view intentionally uses normal flow so the complete prompt can expand; a dynamic-height list virtualizer is deferred for very large galleries. Browser regeneration creates an Attachment through the same-origin CPA service route but deliberately does not write to a workspace because the browser has no trusted agent cwd.
- **Workspace:** normal tool calls write only to the agent session cwd. Dynamic workspace discovery reads DSH's workspace projection for allowlisting; deletion accepts only regular, non-symlink generated-image filenames under canonical explicit roots. New full SHA-256 attachment IDs use full-digest filenames to avoid prefix collisions. Gallery path cleanup accepts canonical full-digest files only; legacy eight-character files are intentionally left as orphan-compatible files by the browser path route. The attachment-aware reverse helper can remove a legacy file only after verifying the full digest. It never authorizes arbitrary browser workspace roots or writes to `process.cwd()`.

## Optional reference-image editing

The CPA contract keeps `generate` backward-compatible and may expose `edit` with provider-neutral `{ data, mediaType }` references. The Host-side Adapter resolves inline DSH Attachments in upload order, supports explicit attachment IDs and workspace-contained paths, and registers `edit_image` only when `service.edit` is available. GPT uses `/images/edits`; Gemini uses multimodal `/chat/completions` data URLs. Older Providers remain generation-only through feature detection.

A Studio native-provider backend, native multi-model comparison, `provider=comfyui`, `image-result-node`, direct provider credential clients, and provider/BYOK settings remain deliberately excluded.

## Verification boundary

The repository tests cover engine-specific request mapping, service-only composition, response validation/metadata, inspiration parsing/routes/cache limits, Gallery normalization/favorite/batch/workspace filters, safe workspace discovery/deletion, legacy image reference paths, and cancellation. `pnpm run typecheck`, `pnpm test`, `pnpm run build`, `pnpm run pack:check`, and a successful `pnpm run pack:artifact` are the release checks; real CPA relay smoke tests require a separately installed Provider and are not performed with credentials in this repository.
