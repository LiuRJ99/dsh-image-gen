# CPA-backed Image Generation Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the forked `dsh-image-gen` project into a standalone native DSH image-generation plugin whose model traffic and credentials are supplied by `dsh-cpa-plugin`, with GPT Image 2 and Gemini Image as the first two internal engines.

**Architecture:** Keep the fork's DSH tool, attachment, image route, workspace-save, conversation card, and Gallery layers. Move all upstream HTTP and credential resolution into a Host service provided by `dsh-cpa-plugin`; the service uses `/v1/images/generations` for GPT Image 2 and `/v1/chat/completions` plus `message.images` for `gemini-3.1-flash-image`. The image plugin exposes only a small engine choice (`GPT Image 2` or `Gemini Image`), while ordinary model selectors hide image-only models.

**Tech Stack:** TypeScript and ESM, Node.js 22+, DSH/Cordis native Bundles, React client slots, DSH Attachment service, `vitest` in `dsh-image-gen`, Node's built-in test runner in `dsh-cpa-plugin`, `pnpm`, and the existing DSH `package.json`/`cordis.patch.yml` packaging model.

- GPT Image 2 traffic continues to use the existing `/v1/images/generations` envelope and parser semantics.
- Generated bytes are persisted by `dsh-image-gen` through DSH Attachment; the CPA service returns normalized bytes and does not own the UI attachment lifecycle.
- Do not commit generated images, local response captures, API keys, or environment-specific endpoints containing credentials.
- Preserve the existing DSH peer range and Node engine unless a build failure demonstrates that the service contract requires a version change.

~~~ts
export const IMAGE_GENERATION_SERVICE = 'dshCpaImageGeneration'

export type ImageEngine = 'gpt' | 'gemini'

export interface CpaImageGenerationRequest {
  engine: ImageEngine
  prompt: string
  aspectRatio?: string
  imageSize?: string
  size?: string
  signal: AbortSignal
}

export interface CpaGeneratedImage {
  data: Uint8Array
  mediaType: 'image/png' | 'image/jpeg' | 'image/webp' | 'image/gif'
}

export interface CpaImageGenerationService {
  generate(request: CpaImageGenerationRequest): Promise<CpaGeneratedImage>
}
~~~

  1. Resolve the CPA route and API key inside the Host.
  2. Map `gpt` to model `gpt-image-2` and path `/images/generations`.

## MVP Completion Criteria

- `dsh-image-gen` contains no direct API-key resolution and no direct Google/OpenAI/DashScope provider configuration.
- `dsh-cpa-plugin` provides `dshCpaImageGeneration` and owns both CPA request paths.
- `generate_image` produces an Attachment-backed image card for GPT Image 2 and Gemini Image.
- The Gallery and workspace-save behavior from the fork remains available.
- Ordinary model selectors hide image-only IDs but retain ordinary Gemini text models.
- `.codex-plugin/plugin.json` and `skills/imagegen/SKILL.md` are packaged alongside the native DSH manifest.
- Unit, typecheck, build, package, and local smoke-test evidence is recorded.

## Explicitly Deferred

Reference-image editing, multi-turn Gemini thought-signature preservation, video-to-image input, multiple output images, and automatic capability discovery from CPA model metadata are not part of the MVP. The service request keeps `aspectRatio`, `imageSize`, and `size` extensible so those features can be added without reintroducing provider credentials into the image plugin.
